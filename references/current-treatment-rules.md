# Current Wastewater Treatment / Technology 判定规则（V1.1 新增）

**回答的问题**：

| Path | 回答 |
|---|---|
| **End-user Path** | 这家企业**现在用什么方案处理废水**？ |
| **Partner Path** | 这家伙伴**现在能提供哪些水处理技术**？ |

**新增原因**：早期实跑中，"已建 ETP / ZLD"与"纯贸易无废水"两种情况在卡上**无法区分**，导致两类误判：
① 已建多座 ZLD 的制造集团 → 被读成"没机会"；
② EPC / 集成商的技术组合（UV/H₂O₂、臭氧、膜、ZLD）无处记录 → 无法判断 BDD 能否切入其组合。

---

## 一、只能使用公开证据

| 允许 | 不允许 |
|---|---|
| 官网环境 / 可持续栏目 | 行业惯例推断"应该会用生化" |
| 年报 · ESG / BRSR / 可持续发展报告 | 同类客户类比 |
| 政府许可 / 环评 / 半年度合规报告 | 第三方 B2B 站的"技术能力"标签 |
| 公开发表的项目案例 / 供应商披露 | 客户未公开的自述（除非在询盘文字中，标注 `客户自述`） |
| 招聘信息中明确载明的设施 / 岗位 | 从"有环保岗"推断"有 ETP" |

**查不到 → 输出 `Unknown`。不得留空、不得用经验值填充。**

> `Unknown` 本身是有价值的输出：它直接说明"该问客户什么"。

### Evidence 标注要求（遵循 `evidence-policy.md`）

| 结论 | 类型 | 要求 |
|---|---|---|
| 官网 / 年报 / 政府文件载明的设施或技术 | **FACT** | 必须有 `Source` |
| 由工艺段推断的处理单元归属 | **INFERENCE** | 必须有 `Reason` + `Confidence` |
| 查不到 | **UNKNOWN** | **必须带三态后缀**（`searched` / `no source` / `not searched`） |

**禁止**：不得因"这类工厂通常用生化"而输出具体单元——行业常识不构成 Source。

## 二、End-user Path · 提取项

从公开来源提取**现有处理方案**，按以下单元归类（可多选，只列已确证的）：

| 单元 | 典型公开表述关键词 |
|---|---|
| 预处理 | 格栅、调节池、隔油、气浮（DAF）、中和、混凝沉淀 |
| 物化 | 化学氧化、混凝絮凝、Fenton、铁碳、气浮 |
| 生化 | 厌氧（UASB / IC）、好氧（活性污泥 / MBBR / SBR）、AO / A²O |
| 膜 | UF、NF、RO、DTRO、MBR |
| 蒸发 / 结晶 | MEE 多效蒸发、MVR、蒸发结晶、干燥 |
| 高级氧化 | 臭氧、UV/H₂O₂、电催化氧化、湿式氧化 |
| 零排放 | ZLD / 零液体排放、近零排放、水回用 |
| 排放去向 | 厂内三级处理、CETP、市政管网、直排、回用 |

**输出格式**：只写单元名 + 定性描述，**禁止输出任何数值区间或技术参数**。

```
Current Wastewater Treatment / Technology:
  物化 + 生化（确证）· ZLD（部分厂区，8 座）· 水回用 42% · 排放去向：厂内三级处理
  Source: E8 / E12
```

## 三、Partner Path · 提取项

从公开来源提取其**可提供的水处理技术组合**：

| 维度 | 记录什么 |
|---|---|
| 技术线 | 该公司公开宣称或案例中使用的工艺单元（同上表口径） |
| 自有 / 集成 | 自有产品线 / 仅集成第三方 / 纯代理分销 |
| 与 BDD 场景重叠度 | 其技术所面向的污染物类型是否与 BDD 场景重叠（**只记事实重叠，不判可行性**） |
| 工艺开放度 | 公司是否公开声明工艺开放 / 只专精单一工艺 |
| 交付模式 | 设备供货 / EPC 总包 / O&M 运营 / 技术授权 |

**输出格式示例**：

```
Current Wastewater Treatment / Technology:
  物化 · 生化 · 膜 · 离子交换 · 气浮 · ZLD · 厌氧沼气
  AOP 线：H₂O₂ + UV、臭氧（自有 Envochem 产品线）
  工艺开放度：自述 verfahrensoffen
  Source: E15 / E16
```

**⚠️ Partner Path 的竞争标注**：若其自有工艺与 BDD 目标场景重叠 → 在 `BDD Relevance` 的附注中标注 `Conflict: 潜在竞争`（红色语义）。**不得隐藏、不得淡化。**

## 四、关键判读规则（V1.1 重点）

### 规则 1 · 已有成熟处理系统 ≠ 无机会

> ❌ **不得因"已建成 ETP / ZLD"直接给出 `BDD Relevance = Low`。**

已建设施只说明"过去用了什么方案"，不说明"未来没有切口"。判读必须同时看**窗口信号**：

| 窗口信号 | 含义 |
|---|---|
| **未闭环比例** | 部分厂区已 ZLD、其余仍在推进中 → 未闭环厂区是窗口 |
| **扩产 / 新建** | 新增产线、新建基地 → 废水增量与新工艺窗口 |
| **标准加严 / 处罚 / 诉讼** | 合规压力上升 → 提标改造窗口 |
| **高浓母液 / 难降解段未覆盖** | 现有主线未覆盖的工艺段 → 补充工艺窗口 |
| **水回用率未达 100%** | 仍有未回用的废水段 |

**只有当以下三项同时成立，才可作为降级依据**：
① 全厂区闭环（无未覆盖段）；② 无扩产 / 无标准加严 / 无处罚；③ 无高浓母液等遗留段。

### 规则 2 · 已有他方技术方案 ≠ 排除 BDD

现有工艺为其他技术路线（生化、膜、UV/H₂O₂ 等）**不构成 `Low` 依据**——BDD 的典型定位是**深度处理 / 提标 / 难降解段补充**，与主线工艺通常是互补关系。

### 规则 3 · Partner Path 不以其自身废水为主要判断依据

> ❌ **不得以"它自己产生多少废水"作为 Partner 的主要判断依据。**

Partner 的判断重点是：**它是否会把 BDD 纳入其交付组合、是否有渠道与项目在手。**

## 五、与其他文件的职责边界

| 文件 | 负责 |
|---|---|
| **本文件** | 现有处理方案 / 技术组合的**提取口径**与判读规则 |
| `lead-signals.md` | 从外部来源检索证据 |
| `bdd-relevance-rules.md` | 消费本文件输出，判定 BDD Relevance |
| `wastewater-signal-map.md` | 从文字识别客户侧信号 |
| `opportunity-type-rules.md` | 判定 Opportunity Type |

**本文件不做技术可行性判断，不输出设备选型、工艺参数与任何数值区间。**
