# Missing Critical Information 生成规则（V1.1）

**用途**：生成主卡 `What Is Missing`，并校验客户已给数据的可靠性。

> **V1.1 变化**：
> ① 字段名 `Missing Critical Data` → **`Missing Critical Information`**（不含技术数据的商务信息同样是关键缺口）；
> ② **新增三级优先级 `Business → Project → Technical`**，按此顺序排列；
> ③ 删除"输出必含建议小试"与固定"寄 5–10 L 水样"（属越界；见 SKILL.md 边界）。

---

## 一、三级优先级（V1.1 核心）

**排列顺序固定为 Business → Project → Technical。** 上级未补齐时，下级不作为主要缺口。

| 级 | 缺什么 | 为什么排这个位置 |
|---|---|---|
| **Business**<br>业务级 | 客户身份与需求性质 | **不确认这些，后面所有信息都没有意义。** 是自用项目还是渠道分销？终端是谁？决策链多长？ |
| **Project**<br>项目级 | 项目是否存在、阶段与时间 | 有需求 ≠ 有项目。项目级信息决定"现在投不投入"。 |
| **Technical**<br>技术级 | 水质与水量参数 | 影响规模与工艺方向，但**属最后一环**，且通常需要客户配合检测。 |

> **反直觉但重要**：传统写法把 COD、水量放在最前。但从**客户开发判断**的角度，
> **"这家到底是不是真实需求方"比"COD 是多少"重要得多**——拿到 COD 但客户是套方案的中间商，等于白干。

---

## 二、Business 级（最高优先）

| # | 信息 | 为什么关键 | 适用 |
|---|---|---|---|
| B1 | 需求性质（自用 / 项目 / 渠道分销） | 决定 Path 与机会类型 | 全部 |
| B2 | 主体全称与工商 / 登记信息 | 主体错 = 全盘错 | 主体未核实或重名时 |
| B3 | 终端客户名称与应用行业 | 渠道型客户的核心 | Partner / Distributor |
| B4 | 项目业主 / 中标方 | 工程型客户的核心 | Partner / EPC |
| B5 | 采购形态（电极 / 模组 / 成套集成 / 代理） | 决定机会类型 | Partner |
| B6 | 决策链与决策人角色 | 决定接触策略 | 全部 |
| B7 | 供应商准入与验证要求 | 影响可推进性 | Partner |

## 三、Project 级

| # | 信息 | 为什么关键 | 适用 |
|---|---|---|---|
| P1 | 是否存在具体项目 / 采购计划 | 区分"有兴趣"与"有项目" | 全部 |
| P2 | 项目阶段（储备 / 设计 / 招标 / 执行） | 判断时间窗 | 全部 |
| P3 | 目标工段（新建 / 提标 / 高浓母液 / 回用） | 决定切入点 | End-user |
| P4 | 目标厂区（多厂区集团） | 落地必须具体 | 集团型 |
| P5 | 时间节点与预算审批节奏 | 判断紧迫度 | 全部 |
| P6 | 现有处理设施的运行问题 | 发现改造窗口 | End-user |

## 四、Technical 级（最低优先）

| # | 信息 | 为什么关键 |
|---|---|---|
| T1 | 水质类型 / 特征污染物 | 决定工艺方向 |
| T2 | 进水 COD 或目标污染物浓度 | 决定污染负荷 |
| T3 | 处理水量 m³/d | 决定规模量级 |
| T4 | 目标限值 / 执行标准 | 决定处理深度 |
| T5 | 盐度 / 氯离子含量 | 影响电极选型与副产物风险 |
| T6 | 现有工艺及运行数据 | 判断兼容性 |

> **注意**：本 Skill 只输出"缺什么、按什么顺序问"，**不输出任何报价状态判断、不输出技术方案、不输出设备选型**。

---

## 五、输出格式

```
What Is Missing:
  [Business]  ① 需求性质（自用 / 渠道分销）  ② 终端客户与应用行业
  [Project]   ③ 是否存在具体废水治理项目及目标工段
  [Technical] ④ 进水 COD  ⑤ 处理水量 m³/d
```

**规则**：
- **最多 5 项**，按 Business → Project → Technical 排列
- 同一级内按对决策影响排序
- 齐全时输出 `None`
- **不得跳过 Business 级直接列 Technical 级**（除非 Business 级已全部确认）

## 六、按客户类型的加问清单

### A. 通用（所有客户）

```
1. 本次需求的来源与性质？（自有项目 / 承接项目 / 客户委托 / 渠道询价）
2. 需求方主体的工商 / 登记全称？
3. 决策由谁参与？目前的推进阶段？
```

### B. End-user 加问

```
4. 需要达到的排放标准或目标限值？有无整改期限？
5. 目标工段：新建 / 提标 / 高浓母液 / 水回用？
6. 现有处理工艺及当前运行中的问题？
7. 进水 COD 及水量（m³/d）？（如有近 3 个月检测报告请一并提供）
8. pH、SS、色度、氯离子 / 含盐量？
```

### C. Partner / EPC 加问

```
9.  项目是否已中标？业主方是哪家？
10. 需要电极 / 模组，还是整套集成配套？
11. 是否需要我方配合投标技术文件？
12. 需求量级与项目时间节点？
```

### D. Partner / Distributor 加问

```
13. 终端客户名称与应用行业？
14. 现有代理产品线（是否含水处理类）？
15. 年采购量预估与交付节奏？是否要求区域保护？
```

### E. Partner / Technology Partner 加问

```
16. 现有工艺组合覆盖哪些单元？哪些场景尚缺方案？
17. 是否有在谈项目可纳入评估？
18. 是否需要联合验证 / 长期技术合作？
```

## 七、参数合理性自检

生成情报卡前做一致性检查，异常项必须回问，**并在附录 A 中标注为 FACT 或 INFERENCE**。

| 检查项 | 异常信号 | 处理 |
|---|---|---|
| COD vs BOD₅ | COD < BOD₅ | 数据错误，回问 |
| 氨氮 vs 总氮 | 氨氮 > 总氮 | 数据错误，回问 |
| 水量 vs 规模 | 与客户描述的产线规模不匹配 | 回问 |
| 检测时效 | 报告超过 6 个月 | 标注"检测时效存疑" |
| 检测资质 | 无 CMA 资质报告 | 标注"数据不可直接用于设计" |
| 单位 | 混用 ppm / mg/L / 万 mg/L | 统一为 mg/L 后确认 |

## 八、客户提供数据的证据标注

| 数据来源 | 类型 | 标注写法 |
|---|---|---|
| 客户提供 CMA 检测报告 | **FACT** | `Source: 客户提供检测报告（{日期}）` |
| 客户方口头 / 文字陈述 | **FACT** | `Source: 客户自述`（Confidence = Low） |
| 客户说"大概""差不多" | **INFERENCE** | 需 `Reason`；或标注"客户口径，未经检测确认" |
| 客户未提及 | **UNKNOWN** | 按三级优先级列入 `What Is Missing` |

**硬规则**：`客户自述` 是合法 Source，但 Confidence 只能为 `Low`。

---

## 九、缺失信息的处理原则

| 缺失情况 | 不要做 | 要做 |
|---|---|---|
| 客户不知道水质数据 | 用同类行业经验值替代 | 列入 Technical 级缺口，建议送检 |
| 客户只给一个 COD 值 | 据此做任何判断 | 列入 Technical 级缺口 |
| 客户说"大概""差不多" | 采信具体数值 | 标注"客户口径，未经检测确认" |
| 客户拒绝提供盐度 / 氯离子 | 跳过 | 列入 Technical 级缺口 |
| **业务级信息缺失（需求性质、主体身份）** | **继续往下问技术参数** | **优先补 Business 级；在补齐前不与技术人员排期** |
| 客户要求"先给个大概价" | 不给任何数字 | 输出缺项清单；**报价属人工 / 商务流程** |
| 已确认存在具体项目 | **不得自行进入小试流程** | 只输出 **"转交技术评估流程"** |

## 十、待校准项

| # | 待确认 | 归属 |
|---|---|---|
| 1 | 三级优先级的项是否需增删 | 销售 + 技术 |
| 2 | 各客户类型加问清单是否需增删 | 销售 |
| 3 | 检测报告时效窗口（现设 6 个月）是否合适 | 技术 |
| 4 | 最小可接项目水量门槛 | 销售 |
| 5 | "转交技术评估流程"的接收方与 SLA | 技术 + 销售 |

## 十一、与其他文件的职责边界

| 文件 | 负责 |
|---|---|
| **本文件** | Missing Critical Information 三级生成 + 参数自检 + 已提供数据的标注 |
| `wastewater-signal-map.md` | 从文字识别客户已提供哪些数据 |
| `evidence-policy.md` | 客户提供数据的 FACT / INFERENCE 标注规则 |
| `customer-type-playbook.md` | 客户类型 / Path（决定加问哪一组） |
| `sales-conclusion-rules.md` | 消费本文件输出判断是否"建议先验证" |

**本文件不输出任何金额、报价状态或技术参数。**
